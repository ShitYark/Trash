## DoD

- Android: пакеты SDK — system-images, build-tools, NDK, платформы — удаляются папкой пакета, в Корзину или навсегда; эмуляторы — папкой `.avd` и `<имя>.ini`. Отказ: эмулятор запущен, образ нужен эмулятору, состояние не прочитать. Emulator, platform-tools, cmdline-tools — только поиск.
- Docker: строки «остановленные контейнеры», «неиспользуемые образы», «кэш сборки» удаляются `docker … prune -f`, сразу; «остальное на диске» — только поиск. Docker Desktop не запущен — отказ.
- conda: окружение — `conda remove -p <путь> --all -y`, кэш — `conda clean --all -y`, сразу.
- Ollama: модель — `DELETE /api/delete` к `127.0.0.1:11434`, сразу. Ollama не запущена — отказ.
- Новые разделы сами не отмечаются; окно очистки и отчёт говорят правду про новые пути.

## Этапы

1. Модель: `ScanItem.isSearchOnly`; категории удаляемые, `isManagerOnly` у Docker, conda, Ollama; новые операции `ManagerRemoval`.
2. Сканеры: операции и поэлементная неудаляемость; Docker — строки по `docker system df` и остаток диска.
3. Защита: узкое правило стража для Android; перепроверки в `Cleaner` — запущенный эмулятор, нужный образ, порядок; `ManagerRemover` — docker, conda, Ollama с проверкой идентификаторов.
4. Окно очистки и отчёт: тексты для новых инструментов.
5. Тесты во временной папке, команды и HTTP подменены.
6. Проверка: сборка, тесты, прогон на диске только на чтение, `make run`.
7. Документация и история.

## Решения

- Android-пакеты — папкой, без `sdkmanager`: в cmdline-tools 23.0 он при первом запуске может скачать Android CLI. Поведение Android CLI после ручного удаления не подтверждено.
- Эмуляторы — сами, без `avdmanager`: ему нужна Java, проверки «запущен» нет ни у него, ни у Android Studio.
- Docker: `-a` у образов и кэша сборки — именно их `docker system df` считает освобождаемыми. Тома и диск — только поиск.
- Ollama — через HTTP-сервер, а не CLI: CLI при выключенном сервере может запустить Ollama.app.
- conda: папку `pkgs` целиком не удаляем — сломаются окружения на симлинках.
