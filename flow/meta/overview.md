# Концепция Claude-flow

Flow проекта Trash построен на трёх принципах. Цель — сделать AI-агента предсказуемым в действиях, экономичным по токенам и удобным именно для AI, а не для человека. Четвёртое правило — специфика продукта: приложение удаляет файлы пользователя.

## Принцип 1. Жёсткость инструкций

Агент следует чётким, явным и однозначным шагам, чтобы не было соблазна интерпретировать задачу по-своему и пропустить часть инструкций.

- **Критическое правило в каждой команде** — запрет преждевременной реализации до подтверждения интерпретации. Минимальное чтение кода для понимания задачи допустимо.
- **Команды-режимы вместо угадывания.** Рабочие — `/dev:analyze`, `/dev:search`, `/dev:code`: в них агент заходит сам по классификации запроса из `AGENTS.md`. Служебные — `/dev:review`, `/dev:meta`, `/dev:history`: вызывает только человек.
- **Нумерованные шаги внутри команд** с явными переходами и правилом «один вопрос за раз».
- **`AGENTS.md`** — рубрикатор и классификатор: описывает проект и направляет в нужный алгоритм. Правки кода начинаются только за барьером подтверждённого плана в `/dev:code`.
- **Хуки** страхуют правила, которые агент может нарушить по инерции: guard-bash перед командой, линтеры в конце сессии.

## Принцип 2. Ленивая загрузка контекста

Минимум токенов на старте, остальное — только под текущую задачу.

- **Автозагрузка:** `AGENTS.md` (через мост `CLAUDE.md` = `@AGENTS.md`) + `root-rule.md` + `response-format.md`. Больше ничего.
- **Глоссарий** грузится лениво — поиском в начале задачи — и ведёт в документ модуля за один переход.
- **Документы `flow/knowledge/**`** — только по переходу из глоссария.
- **История `flow/history/**`** изолирована: её читает субагент `context` и возвращает только пересечения.
- **Мета-документация** не грузится автоматически.

## Принцип 3. Формат под AI, а не под человека

- Табличные индексы с явной колонкой «куда идти».
- Короткие однозначные шаги вместо повествования.
- Явные ссылки на следующий документ.
- Минимум воды, максимум списков и таблиц.
- Глоссарий синонимов и имён типов, чтобы агент находил термин по любому варианту.

## Правило продукта. Безопасность удаления

Trash удаляет файлы пользователя, поэтому flow добавляет к принципам слой защиты:

- root-rule п.2 — агент не удаляет файлы вне проекта и не жмёт «Очистить» в реальном приложении;
- guard-bash блокирует `rm` и `find -delete` вне проекта;
- `code-reviewer` ставит безопасность удаления первым приоритетом;
- контракт безопасности описан в `flow/knowledge/modules/cleanup.md`, его ослабление — только по явному решению с записью в историю.
