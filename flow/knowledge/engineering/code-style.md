# Код-стайл Trash

## Язык и concurrency

- Swift 6 language mode, строгая проверка concurrency. Изоляция по умолчанию — `nonisolated`: `SWIFT_DEFAULT_ACTOR_ISOLATION` в проекте не задан.
- Работа с диском — обход папок, размеры, удаление — только в `@concurrent` функциях сервисов. На main actor диск не трогаем.
- Состояние UI — `@MainActor @Observable final class`. Модели и сервисы — `Sendable` структуры и enum.
- `FileManager` не храним в свойствах: он не `Sendable`. Используем `FileManager.default` по месту.
- В длинных циклах проверяй `Task.isCancelled`.

## Безопасность удаления

- Любое удаление — только через `Cleaner`, который спрашивает `SafetyGuard.canDelete`. Прямые `removeItem` / `trashItem` в других местах кода запрещены.
- Новая категория очистки = новые разрешённые корни удаления. Корень обязан лежать внутри домашней папки и не совпадать с защищённым путём.
- Ошибка одного элемента не прерывает обработку остальных — собирается в отчёт.
- Деструктивное действие в UI — только после диалога подтверждения; клавиатурные шорткаты на удаление не вешаем.

## Переменные и свойства

- Не называй переменные одной буквой.
- Давай короткие, но достаточные для понимания контекста имена.

## Порядок объявления членов типов

- Для `class`, `struct`, `enum`, `extension` соблюдай единый порядок объявления членов.
- Сначала свойства и константы: более внешние (`internal`, без модификатора) — затем `private`.
- Вычисляемые свойства относятся к блоку свойств и не располагаются после методов.
- После свойств — `init` и другие инициализаторы.
- Затем остальные методы: сначала внешние, затем `private` helper-методы.
- Во view: `body` идёт сразу после свойств, вспомогательные вью и методы — ниже.
- В тестах private helper-методы размещай после тестовых методов.

## Optional unwrap

- **Никогда не используй force unwrap `!`** — ни в коде, ни в тестах. Сюда же `try!` и `as!`.
- В коде — `guard let` / `if let` / `??`; nil обрабатывается явно.
- В тестах — `try #require(...)`, тест помечается `throws`.

## SwiftUI

- Владелец состояния — `@State private var model`; дочерним вью — `let model` или `@Bindable var model`, если нужны биндинги.
- Изменения выбора — через методы view model (`setSelected` и биндинги из `CleanupViewModel+Bindings`), а не мутацией коллекций из вью.
- Групповой чекбокс «выбрать всё» — `Toggle(sources:isOn:)` по биндингам элементов: частичный выбор показывается смешанным, а не пустым.
- Размеры показываем через `.formatted(.byteCount(style: .file))`.
- Строки UI — по-русски.
- Минимальная версия — macOS 14: `@available` для более старых версий не нужен.

## Условия и коллекции

- Короткое условие и открывающая скобка — на одной строке.
- Первый и последний элементы — через `first` / `last`.

## Тесты

- Подвохи макросов Swift Testing — `swift-testing-gotchas.md`.

- Swift Testing: `import Testing`, `@Test`, `#expect`, `#require`.
- Файловые тесты — во временной папке с уникальным именем, уборка в `defer`. Реальный `~` в тестах на удаление не используется никогда.
- Тесты выполняются параллельно — общих файлов и глобального состояния между тестами нет.

## Комментарии

- По-русски, коротко: зачем, а не что. Документирующий `///` — у публичных точек входа сервисов и неочевидных свойств.
