# КРИТИЧЕСКОЕ ПРАВИЛО: НЕ ВЫДУМЫВАТЬ. НЕ УГАДЫВАТЬ. ПРОВЕРЯТЬ.

> Применяется ко **всем агентам** flow — code, search, analyze, review, meta, субагенты (`code-reviewer`, `context`).
> Ниже — что именно требует проверки, как проверять в этом проекте и что считается доказательством.

## АБСОЛЮТНЫЙ ЗАПРЕТ

**Любое фактическое утверждение должно быть подтверждено проверкой ДО того, как оно написано пользователю. Без исключений.**

## Что требует проверки (универсальное)

| Утверждение | Как проверить |
|---|---|
| «Файл / тип / метод / переменная существует» | Grep/Glob |
| «Этот код работает так-то» | Read файла, не по памяти |
| «Фреймворк / API умеет X» | context7 / документация Apple, не память |
| «Все N мест обновлены» | проверить КАЖДОЕ (grep-счётчик), не экстраполировать с первых двух |
| «✓ работает / ✓ PASS» | реальный запуск с чтением фактического вывода |

## Особенно для Trash

| Утверждение | Как проверить |
|---|---|
| «Тесты зелёные» | только `make test`: код выхода 0, `** TEST SUCCEEDED **` и «Тестов прошло: N из N». Счёт по строкам лога не доказательство: строки `xcodebuild` перемешиваются и рвутся |
| «Сборка проходит» | `make build`: код выхода 0 и `** BUILD SUCCEEDED **` |
| «Новый файл попал в сборку» | файл лежит внутри `Trash/` или `TrashTests/` — синхронизируемые папки; вне них в сборку не попадёт |
| «Путь X будет / не будет удалён» | тест на `SafetyGuard.canDelete` или чтение `SafetyGuard.swift` и корней `CleanupCategory`; не по памяти |
| «Приложение видит папку Y» | App Sandbox выключен, но TCC действует: `~/.Trash` и ряд папок требуют Full Disk Access. Проверка — фактический прогон скана, а не предположение |
| «Размер совпадает с Finder» | сверка с `du -sk <путь>` — только чтение |
| «API доступен в macOS 14» | документация через context7 / Apple, атрибуты `@available` в SDK |
| «UI выглядит так-то» | скриншот запущенного приложения; нет доступа к записи экрана — так и скажи |
| «Поведение — баг» | история модуля через субагента `context` + `git log -S` / `git blame`: может быть осознанным решением прошлой задачи |

## Правильный паттерн

```
Не знаю точно → проверяю (grep/read/запуск/MCP) → отвечаю с пруфами (файл:строка, фактический вывод)
```

1. **Не уверен на 100%** → сначала проверь.
2. **Нет способа проверить** → скажи «не могу проверить, потому что …», а не «должно быть так».
3. **Никогда** не строй «правдоподобный» ответ на предположениях; «я думаю, что…» для фактов запрещено.
4. **Чем увереннее хочется ответить — тем больше причин проверить.**

## Антипаттерны (запрещено)

- «Должно быть примерно так…» / «Скорее всего этот метод…» — без проверки
- «Я проверил, всё работает» — без реального запуска и чтения вывода
- «Тесты зелёные» — без `make test`
- «Удаление безопасно» — без теста на `SafetyGuard` для нового пути

## Формула

> Проверка > Уверенность.
> «Не знаю + проверил» = полезный ответ. «Не знаю + уверенно ответил» = активный вред: в этом проекте — удалённые файлы пользователя.
