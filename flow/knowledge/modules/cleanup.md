# Очистка

Удаление выбранных элементов — в Корзину, навсегда или командой менеджера (`simctl`, `brew`). Каждый путь, удаляемый файлами, перед удалением проверяется `SafetyGuard`; удаление через менеджер — своей защитой `ManagerRemover`. Это самый рискованный модуль приложения: ошибка здесь удаляет данные пользователя.

## Точки входа

- `Cleaner.clean(_:permanently:)` — удаляет список `ScanItem`, возвращает `CleanupReport`.
- `SafetyGuard.canDelete(_:)` — разрешает удаление только строго внутри разрешённых корней.
- `ManagerRemover.remove(_:paths:)` — удаление через менеджер по операции `ManagerRemoval` элемента.
- `CleanupReport` — удалённые URL, куда они ушли — `movedToTrash`, `deletedPermanently`, `removedByManagers`, — освобождённые байты, ошибки. Объявлен в `Trash/Models/ScanResult.swift`.

## Контракт безопасности

Ослаблять только по явному решению пользователя, с записью решения в историю модуля.

1. **Разрешённые корни** = корни удаляемых категорий (`isDeletable`) — `CleanupCategory.roots(home:)`, кроме симуляторов, версий языков, Android, команд, служб, кэшей в данных программ и установщиков: у них узкие правила, пункты 5–10. Добавление удаляемой категории расширяет зону удаления. Корни вложены друг в друга: `Caches/com.apple.dt.Xcode` разрешён и как корень «Кэшей Xcode», и как потомок `~/Library/Caches`.
2. **Неудаляемое** — `Cleaner` отклоняет **до** проверки `SafetyGuard`, с причиной в отчёте; это две независимые защиты:
   - категорий без `isDeletable` сейчас нет — список явный, без `default`: новая категория обязана попасть в него сознательно;
   - элементы без `ScanItem.isDeletable` в удаляемых категориях: в разделах `isManagerOnly` — рантаймы, Homebrew, Docker, conda, Ollama — удаляется только элемент с операцией менеджера: встроенный рантайм, cask, явно поставленная или закреплённая формула, остаток диска Docker, окружение без `bin/conda` остаются только для поиска;
   - элементы с `ScanItem.isSearchOnly`: emulator, platform-tools, cmdline-tools в Android SDK; в «Программах вне Homebrew» всё, кроме битых ссылок; работающие службы.
3. **Правило — по категории элемента** (`canDelete(_:as:)`): программа проходит только правилом программ, остаток — только правилом остатков, остальное — корнями; путь с `..` не принимается. **Программы — узким правилом, не корнем:** удалить можно только сам `.app` прямо в папке программ (`/Applications`, его подпапка, `~/Applications`) — не папку, не содержимое бандла, не системную программу (настоящий путь в `/System`), не сам Trash. Всегда в Корзину через `Recycler`; программу root, которую macOS не дал переместить, — через Finder с паролем администратора, тоже в Корзину. Ссылку Finder не получает. Запущенную `Cleaner` не удаляет.
4. **Остатки — узким правилом, не корнем:** удалить можно только элемент с именем-идентификатором (`LeftoverPolicy.owner`) прямо в папке данных программ `~/Library/<…>`. Перед удалением `Cleaner` строит свежий каталог программ и отказывает, если программа снова установлена.
5. **Симуляторы — узким правилом, не корнем:** только папка с именем-UUID прямо в `CoreSimulator/Devices` — не `device_set.plist`, не содержимое симулятора. Папку без симулятора `Cleaner` удаляет файлами только после свежего `simctl list`: симулятор, появившийся после скана, или `simctl` без ответа — отказ.
6. **Версии языков — узким правилом, не корнем:** только видимая папка, не ссылка-псевдоним, прямо в папке версий менеджера (`ToolCatalog.versionManagers`), список папок читается заново при каждой проверке. Перед удалением `Cleaner` заново определяет активную версию: активная и неопределённая — отказ. Правила определения — `terminal.md` → «Сведение активной версии к папкам».
7. **Android — узким правилом, не корнем:** пакет SDK — папка с `package.xml` на своей глубине: `system-images/<api>/<tag>/<abi>`, `build-tools/<версия>`, `ndk/<версия>`, `platforms/<платформа>`; эмулятор — `<имя>.avd` прямо в `~/.android/avd`. Не ссылка, не скрытое. Перед удалением `Cleaner`:
   - эмулятор запущен — отказ: живой PID в lock-файле или `multiinstance.lock`, занятый `flock`;
   - удаляет `<имя>.ini`, затем папку `.avd`, в одном режиме; на месте ini не обычный файл — папка или ссылка — отказ: `canDeleteEmulatorConfig`;
   - образ нужен эмулятору по свежему чтению — отказ. Эмуляторы — `.avd` в папке и по `path=` из `<имя>.ini`. Папку эмуляторов не прочитать — нет прав, битая ссылка, не папка — или образ хоть одного эмулятора не определить — тоже отказ; «эмуляторов нет» — только когда папки нет вовсе;
   - эмуляторы очистки удаляются раньше образов; эмулятор вне `~/.android/avd` — только поиск.
8. **Битые ссылки и службы — узкими правилами, в том числе вне `~`** — решение пользователя от 2026-10-13:
   - ссылка — битая, не скрытая, прямо в папке команд: `/usr/local/bin`, `~/.local/bin`, `~/.cargo/bin`, `~/go/bin`; удаляется сама ссылка — цели нет;
   - plist — обычный файл, не ссылка, прямо в `~/Library/LaunchAgents`, `/Library/LaunchAgents` или `/Library/LaunchDaemons`; `/System` — никогда. Перед удалением `Cleaner` перечитывает plist: программа снова на месте или метку не разобрать — отказ;
   - «нет файла» — только `ENOENT`: программа в закрытой правами папке не «удалена», ссылка на `/Volumes/…` не «битая» — диск подключат снова.
9. **Кэши в данных программ и установщики — узкими правилами** — `OtherDataScanner`: папка-кэш Chromium по имени рядом с `Local State` или `Preferences`, до глубины 4, не в папке остатка удалённой программы; установщик `.dmg`, `.pkg`, `.xip` прямо в Загрузках. Перед первым кэшем программы `Cleaner` проверяет её папку `lsof -t +D` — прямо перед удалением: до этого могли идти долгие команды менеджеров. Любой вывод — PID процесса или ошибка — отказ «программа запущена»; `lsof` не ответил за 60 с — отказ. Решает вывод, а не код выхода: `lsof` выходит с 1 и тогда, когда нашёл процессы. `lsof` запускается напрямую, с ошибками в выводе — `CommandRunner.system(timeout:answersWithAnyStatus:)`, — чтобы тайм-аут останавливал его самого.
10. **Папки симуляторов, версий языков, Android, команд и служб, `Application Support` и Загрузки — не корни:** другие разделы их не получают, даже если элемент подделан под чужую категорию.
11. **Сам корень удалить нельзя** — только то, что внутри: компонентов пути у цели строго больше, чем у корня, и цель начинается с компонентов корня.
12. **Сравнение — по компонентам пути, не по строковому префиксу:** `Caches/x` разрешён, `CachesBackup/x` — нет.
13. **Сохраняемые папки внутри разрешённых корней — никогда** (`keptFolders`): глобальное хранилище Bun `~/.bun/install/cache/links` и всё внутри. Вторая защита после исключения в сканере; источник — `ToolCatalog.Cache.keeps`.
14. **Защищённые пути — никогда:** `/`, `/System`, `/Library`, `/Applications`, `/Users`, `/private`, `/usr`, `/bin`, `/sbin`, `/var`, `/etc`; домашняя папка и её `Library`, `Documents`, `Desktop`, `Downloads`, `Pictures`, `Movies`, `Music`, `Applications`.
15. **Нормализация:** `.` и `..` убираются, симлинки в родительских папках раскрываются, сам элемент — нет. Удаляется ссылка, а не то, на что она указывает.
16. **Режим:** `permanently == false` → `FileManager.trashItem`, восстановимо; `true` → `removeItem`. Категория с `alwaysDeletesPermanently` — сейчас это Корзина — всегда `removeItem`. Программы (`isApplicationBundle`: установленные программы и копии Xcode) — всегда `Recycler`, в Корзину, независимо от выбора; запасной путь через Finder удалить навсегда не может. Элемент с операцией менеджера — всегда командой менеджера, сразу и без Корзины.
17. **Ошибка одного элемента не прерывает очистку:** строка в `failures`, остальные элементы удаляются дальше.
18. **Освобождённое место** — сумма `size` удалённых элементов из скана; после удаления не пересчитывается.

### С паролем администратора

Ссылки, службы и порты MacPorts в системных папках, куда нельзя писать, удаляет root. Решение пользователя от 2026-10-13: это не программы — запасной путь программ «только Finder и только в Корзину» не меняется.

1. **Root — только для фиксированных системных папок** — `AdministratorScript.isNeeded`, общее для окна очистки и `Cleaner`: `/usr/local/bin`, `/Library/LaunchAgents`, `/Library/LaunchDaemons` без права записи и MacPorts, если `var/macports` не свой. Своя папка без права записи — отказ «нет права записи», а не root: её права мог поменять и не администратор, а root пошёл бы по подменённому пути.
2. **Один скрипт на очистку** — `AdministratorScript.run`: `/usr/bin/osascript` с `do shell script … with administrator privileges`, в фоне, тайм-аут 10 минут на пароль и шаги. Кэш авторизации по TN2065 — только для того же скрипта, поэтому шаги не разбиваются. Ошибку AppleScript скрипт возвращает строкой: stderr `osascript` не читается.
3. **Каждый шаг под root перепроверяет себя** — в подоболочке, через `cd -P` в папку и сверку `pwd -P` с физическим путём, который проверил страж; удаляется `./<имя>`:
   - ссылка: `[ -L ] && [ ! -e ]` — иначе «изменилось», не тронута; `rm -f --` удаляет саму ссылку;
   - служба: обычный файл, не ссылка, `Label` из `plutil` совпадает, программы нет — root видит и закрытые правами папки. Служба **не выгружается**: по метке можно снять другую, живую службу с той же меткой; без программы эта и так не запустится, после перезагрузки её не будет;
   - порт: `port -N uninstall <имя> @<версия>`; имя и версия проверены `ManagerRemover.isPortName` и `isPortVersion`, версия — в свежем `port installed inactive`; `port` или его папку может переписать пользователь — отказ «права смешаны».
4. **Экранирование:** каждое значение — в одинарных кавычках для `sh`, `'` → `'\''`; весь скрипт — литералом AppleScript, `\` и `"` экранируются; скрипт — аргументом `osascript`, без shell. Утилиты — по абсолютным путям, `PATH` задаётся в начале.
5. **Статус** — строка `<номер> done|changed|failed <код>` на шаг, вывод команд — в `/dev/null`; скрипт всегда выходит с 0. Нет строки шага — отказ «нет ответа».
6. **Отмена и сбой:** пароль отменён — `-128` или `-60006` — все шаги от root в отказах, остальное удаляется; флаг отмены Finder — отдельный. Скрипт прерван или упал — ссылки и plist, которых больше нет на диске, считаются удалёнными, остальное — в отказах.
7. **Без Корзины:** удалённое от root — «навсегда», порты — «через менеджер».
8. **`port reclaim` не запускается:** без терминала он молча удаляет и неотмеченные порты.

### Удаление через менеджер

Файлы удаляет не `Cleaner`, а `simctl` или `brew`, поэтому корни стража тут не работают — вместо них своя защита. Решение пользователя от 2026-10-12: «только поиск» был временным.

1. **Операция `ManagerRemoval` — только из вывода менеджера при скане:** `.simulator(udid:)`, `.runtime(identifier:runtimeIdentifier:)`, `.brewUninstall(formula:)`, `.brewCleanup(formula:)`.
2. **`Cleaner` до команды:** раздел операции совпадает с разделом элемента; у симулятора UDID операции — имя папки элемента.
3. **Идентификаторы — проверенные:** UUID, `com.apple.CoreSimulator.SimRuntime.` с буквами, цифрами, `.` и `-`, имя формулы из ASCII-букв, цифр и `@+._-` с буквы или цифры. Ключ вроде `--force` или путь не пройдёт.
4. **Команды фиксированные, аргумент — только идентификатор:**
   - `simctl delete <udid>`, `simctl runtime delete <id>`;
   - `brew uninstall --formula --force <формула>`, `brew cleanup <формула>`;
   - `docker --host unix://~/.docker/run/docker.sock` + `image prune -a -f`, `builder prune -a -f`, `container prune -f` — всегда движок Docker Desktop, не текущий контекст: тот может смотреть на сервер, colima или OrbStack. Тома никогда. Образы раньше контейнеров: иначе `image prune -a` снёс бы и образы только что удалённых контейнеров;
   - `<база>/bin/conda remove -p <окружение> --all -y`, `<база>/bin/conda clean --all -y`. conda — `bin/conda` в папке с `conda-meta`; окружение — папка прямо в `envs` с `conda-meta`, не ссылка, и путь совпадает с элементом: база и посторонняя папка не пройдут;
   - Ollama — `curl -q --noproxy '*'` с `DELETE http://127.0.0.1:11434/api/delete`: без `~/.curlrc` и прокси. Имя модели — ASCII-буквы, цифры и `._:/-_` с буквы или цифры, без `..`. После ответа 200 отсканированный манифест должен исчезнуть — иначе сервер удалил одноимённую модель в другой папке, отказ в отчёте.
5. **Свежее состояние перед командой:** симулятор — только в списке `simctl` и в состоянии `Shutdown`; рантайм — только если им не пользуется ни один симулятор; формула для `uninstall` — только незакреплённая: ссылки `<префикс>/var/homebrew/pinned/<формула>` нет. Симуляторы очистки идут раньше рантаймов.
6. **`brew` — без автоудаления:** через `/usr/bin/env HOMEBREW_NO_AUTOREMOVE=1 HOMEBREW_NO_AUTO_UPDATE=1 HOMEBREW_NO_ENV_HINTS=1`. Без этого `brew uninstall` сам удалил бы ставшие ненужными зависимости, которые никто не отмечал.
7. **`brew cleanup` — только после холостого прогона:** `--dry-run` должен удалить ровно отмеченные версии формулы в `Cellar` и, кроме них, только файлы кэша загрузок `~/Library/Caches/Homebrew`. Иначе — отказ «brew cleanup удалил бы не ровно отмеченное».
8. **Одна команда на операцию:** отметки Homebrew связаны по формуле, итог команды — для всех элементов группы. После `brew` путь элемента, оставшийся на месте, — отказ «Менеджер оставил это на месте».
9. **Тайм-аут команды — 5 минут.**
10. **«Освобождено» у docker, conda и Ollama — оценка из скана:** Docker считает в десятичных единицах, conda и Ollama — без файлов, общих с другими окружениями и моделями. Место от Docker macOS получает через несколько минут.

## Связанные модули

- `scanning.md` — источник корней и элементов.
- `xcode.md` — какие категории Xcode пока только находятся и почему.
- `applications.md` — правила «программа установлена» и «уверенный остаток».
- `terminal.md` — удаляемые кэши Терминала и то, что рядом с ними не удаляется: настройки Gradle, `~/.npmrc`, `~/.cargo/bin`, `~/.pub-cache/bin`.
- `main-window.md` — окно очистки: подтверждение перед удалением и отчёт после.

## Ключевые сценарии

- «Очистить» → окно очистки с выбором «Переместить в Корзину» / «Удалить навсегда» → `CleanupViewModel.cleanSelected(permanently:)` → `Cleaner` → удалённые элементы убираются из результатов → отчёт в том же окне.

## Нюансы

- `trashItem` кладёт элементы в `~/.Trash` — после повторного скана они видны в категории «Корзина».
- Файлы, занятые системой или защищённые SIP/TCC, не удаляются — попадают в `failures` с текстом ошибки.
- Тесты удаления работают только во временной «домашней папке»: `ScannerAndCleanerTests` создаёт `TrashTests-<UUID>` в `temporaryDirectory` и убирает её в `defer`.
- `SafetyGuardTests` использует несуществующий `/Users/tester`: `resolvingSymlinksInPath` возвращает несуществующий путь без изменений, поэтому проверки детерминированы. Исключение — узкие правила симуляторов и версий: папки asdf и mise перечисляются с диска, поэтому их тест строит временную папку.
- `ManagerRemovalTests` подменяет `simctl` и `brew` через `CommandRunner` и записывает каждую команду целиком — исполняемый файл и аргументы; настоящие команды не запускаются.
