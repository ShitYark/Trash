# Trash

macOS-приложение для очистки системы от мусора: кэши, журналы, артефакты Xcode, Корзина. SwiftUI, Swift 6, macOS 14+, без App Sandbox.

Приложение удаляет файлы пользователя — **безопасность удаления важнее любой другой цели задачи**.

Коммуникация с пользователем — на русском.

## Карта репозитория

- Код: `Trash/` — приложение (`App/`, `Models/`, `Services/`, `ViewModels/`, `Views/`); `TrashTests/` — тесты на Swift Testing. Проект — `Trash.xcodeproj` с синхронизируемыми папками: новый файл в `Trash/` или `TrashTests/` попадает в сборку без правки `project.pbxproj`.
- `Makefile` — сборка, тесты, запуск, проверки flow.
- `flow/` — знания, правила, история, планы и meta-документация flow.
- Логика агента: `.claude/commands/dev/` (команды `/dev:*`) и `.claude/agents/` (субагенты).

## Где искать знания (`flow/`)

- `flow/rules/glossary.md` — **точка входа в знания**: один файл, термин → документ модуля за один переход.
- `flow/knowledge/` — документация модулей и инженерные правила.
- `flow/project-map.md` — вспомогательная карта (когда глоссария недостаточно).
- `flow/meta/` — документация про сам flow (формат, планы улучшений). Не для обычных задач.
- `flow/history/` — хроника правок модулей. **Изолирована** от навигации по знаниям: подключается отдельно (через субагента `context`) при работе над модулем, чтобы не засорять контекст.

## Как вести задачи

**Классифицируй запрос сам и иди по нужному алгоритму** — пользователь не обязан знать команды.

| Запрос выглядит так | Алгоритм | Как заходишь |
|---|---|---|
| «не работает», «сломалось», «удалил не то», «должно быть по-другому» — жалоба на поведение | `/dev:analyze` | сам, молча |
| вопрос по коду, логике или данным; разбор лога или краш-репорта | `/dev:search` | сам, молча |
| правка кода, новая функция, тесты | `/dev:code` | объяви «задача на разработку, иду по алгоритму `/dev:code`» и начни |

Запрос подходит под два маршрута — выбирай по цели ответа: нужен вердикт «баг или задумано» → `/dev:analyze`; нужно объяснение или находка → `/dev:search`; нужна правка → `/dev:code`. Не подошло ничего или цель неясна — спроси пользователя, не угадывай.

Зайти в алгоритм — значит прочитать `.claude/commands/dev/<команда>.md` и выполнять его шаги по порядку. Интерпретацию, подтверждения и остановки внутри команды не пропускай: правки кода в `/dev:code` начинаются только после подтверждённого плана.

Служебные команды вызывает человек — по собственной инициативе в них не заходи (явный вызов их шага из другой команды — например, архивация истории из `/dev:code` — разрешён): `/dev:review` (review изменений), `/dev:meta` (изменения самого flow), `/dev:history` (хроника модуля).

Логика процессов живёт в `.claude/commands/` и `.claude/agents/`. Это Claude-only flow: команды стандартизированы под Claude Code, аналогов для других агентов нет.

## Актуальные API фреймворков

Для справки по API Swift, SwiftUI, Foundation и других библиотек — context7, а не догадки по памяти: MCP `resolve-library-id` → `query-docs`; MCP нет — CLI `npx ctx7@latest library "<название>" "<вопрос>"` → `npx ctx7@latest docs <id> "<вопрос>"`. Не больше 3 запросов на вопрос. Для рефакторинга, бизнес-логики и общих концепций не нужен.
