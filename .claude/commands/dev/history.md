# Workflow: history

Вся коммуникация ведётся только на русском языке.

Единая команда для хроники изменений модуля — `flow/history/<module>-history.md`: **генерация** из git и **архивация**. Формат файла и записей — `flow/meta/conventions.md` → «Формат записи истории модуля» и «Архивация истории модуля».

> Инкрементальное дополнение истории по ходу задач делается автоматически в `/dev:code` Шаг 9. Отдельный запуск `/dev:history` нужен для **генерации с нуля** или **архивации**.

**Вход:** `$ARGUMENTS` — имя модуля (например `cleanup`). Пусто — спроси.

---

## Шаг 0 — Определи режим

Проверь `flow/history/<module>-history.md`:

- **не существует** → режим ГЕНЕРАЦИЯ;
- **существует** → покажи размер (`wc -c`, токены ≈ байты / 2.42) и спроси:

```text
История модуля <module> уже есть (N байт, ~M токенов).

1 — Перегенерировать из git (файл перезаписывается целиком, решения из записей теряются)
2 — Архивировать (вынести старые записи в периодные файлы)
3 — Отмена
```

Порог архивации — ~44 000 байт: больше — назрела, предложи активно; меньше — помечай вариант 2 как преждевременный.

**Жди явного ответа.**

# Режим ГЕНЕРАЦИЯ

> **КРИТИЧЕСКОЕ ПРАВИЛО.** Перегенерация перезаписывает файл целиком: поля «Решения» восстановить из git нельзя. Существующий файл — только после явного подтверждения в Шаге 0.

## Шаг 1. Источник файлов модуля

1. Документ `flow/knowledge/modules/<module>.md` существует и содержит `### Ключевые файлы`. Нет — остановись: «нет источника списка файлов модуля; дополни документ через `/dev:code` или `/dev:meta`».
2. Возьми пути из `### Ключевые файлы` и сверь с правилами модуля в `flow/meta/code-to-module-map.json`. Файл заявлен в доке, но не покрыт картой — предложи patch карты отдельным сообщением и жди ответа (1 — применить / 2 — пропустить).

## Шаг 2. Коммиты

```bash
mkdir -p tmp/<module>-history
git log --no-merges --pretty=format:'%H|%ad|%s' --date=short -- <файлы модуля> > tmp/<module>-history/commits.tsv
```

- Коммиты с `[skip-doc-check]`, которые меняли только `flow/` — не записи модуля, пропусти.
- Коммитов больше 100 — спроси, какой диапазон брать.

## Шаг 3. Записи

Для каждого коммита — одна запись:

- заголовок `#### YYYY-MM-DD — <subject коммита>` — дословно;
- `Суть:` — по `git show --stat <hash>` и диффу затронутых файлов модуля, 1–2 предложения;
- `Файлы:` — файлы модуля из коммита;
- `План:` — если в `flow/plans/` есть план с той же сутью;
- `Решения:` — **только** если решение прямо следует из диффа, плана или комментария в коде. Не выдумывай (root-rule п.12).

Записи — по дате, новые сверху. Модуль крупный — группируй по областям из комментариев `(<тип> — <область>)` в «Ключевых файлах».

## Шаг 4. Запись и проверка

1. Запиши файл: шапка по образцу соседних файлов истории, `## Активные записи`, записи.
2. Размер больше ~44 000 байт — сразу режим АРХИВАЦИЯ ниже, в этой же сессии.
3. Отчёт: число записей, диапазон дат, топ-3 крупных изменения, пропущенные коммиты.
4. Сообщение коммита: `Сгенерирована история модуля <module> [skip-doc-check]`.

# Режим АРХИВАЦИЯ

> **КРИТИЧЕСКОЕ ПРАВИЛО.** Запускай только по явному решению пользователя **или по автотриггеру из `/dev:code` Шаг 9** — срабатывание порога равнозначно решению. Главный файл меньше 100 строк — архивация бессмысленна, скажи и не запускай. Перед переписью главного файла убедись, что архивные файлы созданы корректно.

## Шаг 1. Параметры

Вызов автотриггером — проверки выполни молча, без вопросов. Ручной запуск — покажи блок:

```text
Параметры архивации:

Модуль: [имя]
Главный файл: [N байт / ~M токенов]
Окно активного периода: [N месяцев — и почему]
Граничная дата: [YYYY-MM-DD]
Архивные периоды: [кварталы]

1 — ✅ Продолжаем
2 — ❌ Скорректировать
```

Окно подбираешь сам: главный файл после архивации ≤ 18k токенов с запасом на 5–10 записей. Ориентиры — `flow/meta/conventions.md` → «Пороги и окно».

## Шаг 2. Разбор

1. Посчитай записи: `grep -c '^#### ' <файл>` — это число для проверки целостности.
2. Прочитай главный файл; не влезает в Read — `grep -n '^#### '` и чтение порциями.
3. Запись с датой раньше граничной — архивная, остальные — активные. Архивные сгруппируй по кварталам `YYYY-QN`, сохраняя группировку по областям.

## Шаг 3. Архивные файлы

Для каждого квартала — `flow/history/<module>-history/<YYYY-QN>.md`:

```markdown
# История изменений: <module> — <YYYY-QN>

> Архивные записи периода. Возврат к главному файлу: [../<module>-history.md](../<module>-history.md).

## Дайджест периода

[по формату conventions → «Дайджест периода»]

## Записи периода

[полные записи]
```

Квартал уже есть — дополни его, не перезаписывая.

## Шаг 4. Главный файл

1. Шапка без изменений + строки метаданных — отдельными пунктами, обновляются **заменой**:
   - `_последняя архивация: YYYY-MM-DD (окно: N месяцев, с YYYY-MM-DD)._`
   - `_состояние: <норма | свёртка исчерпана, нужен пересмотр окна>._`
2. `## Активные записи` — записи за окно. Не влезают в ~18k токенов — компактный формат: адаптивный N ≤ 12 свежих полных, остальные одной строкой с сохранением решений «намеренно».
3. `## Архив` — по строке на период, новые сверху: `### YYYY-QN (M правок) — [полные записи](<module>-history/YYYY-QN.md). Топ: <тема> (n); <тема> (n)`.

## Шаг 5. Проверка

- **Целостность:** записей до = полных и компактных активных после + записей в архивных файлах этой архивации.
- **Размер:** `wc -c` / 2.42 < 18k токенов. Не влезает — уменьшай N. Окно молча не меняй: свёртка исчерпана — строка состояния и рекомендация пересмотреть окно в отчёте, решение за человеком.
- Полный `python3 flow/scripts/check-links.py flow/history`.

## Шаг 6. Отчёт и коммит

1. Архивные файлы — периоды и число записей
2. Главный файл — новый размер
3. Топ-темы периодов
4. Сообщение коммита: `Архивирована история модуля <module>: записи старше N месяцев [skip-doc-check]`
