# Workflow: meta

Вся коммуникация ведётся только на русском языке.

Руководствуйся следующими правилами при работе над задачами в режиме `/dev:meta`.

---

> **КРИТИЧЕСКОЕ ПРАВИЛО — читай первым.**
>
> 1. **Порядок.** Шаги 1 → 6 выполняются строго по номерам, без перескоков.
> 2. **Один вопрос за раз.** Задал вопрос — сообщение на этом заканчивается.
> 3. **Автозагрузка — отдельное согласование.** Изменения в `CLAUDE.md`, `AGENTS.md`, `root-rule.md`, `response-format.md` (грузятся каждую сессию) и `glossary.md` (первый вход в знания) показывай пользователю **дословной строкой** до внесения — это влияет на любую будущую сессию.
> 4. Остальные остановки — условные: спрашивай, когда есть развилка или необратимое действие, а не ради ритуала.

---

# Шаг 1. Сбор контекста

Прочитай в этом порядке:

1. `flow/rules/root-rule.md` — **уже загружен** через `AGENTS.md`
2. `flow/rules/glossary.md` — строки затрагиваемых инструментов ищи поиском
3. `flow/meta/overview.md` — принципы flow: любое изменение их соблюдает
4. `flow/meta/structure.md` — карта файлов и правила автозагрузки
5. `flow/meta/conventions.md` — правила формата
6. `flow/meta/plans/README.md` — индекс планов и workflow статусов

```text
Интерпретация запроса:

Текст: [как ты понял задачу]
Целевой результат: [что должно получиться]
Затронутые файлы flow: [перечень]
Влияние на стартовый контекст: [да / нет — трогаем ли файлы автозагрузки или глоссарий]
```

**Правило остановки.** Интерпретация добавляет предположения, выбор между вариантами или трогает файлы автозагрузки — добавь вопрос «Всё верно? 1 — ✅ продолжай / 2 — ❌ нужно исправить» и **остановись**. Тривиально совпадает — продолжай.

# Шаг 2. План в системе планов

## Самопроверка при разделении плана

Выделяешь новый план из существующего — проверь, что у каждого получившегося плана остаётся полезная для AI функция: его читают и на его основе принимают решения. План-архив, который никто не откроет, — сигнал пересмотреть границы.

## Задача связана с существующим планом

1. Найди план в таблице `flow/meta/plans/README.md`
2. Прочитай его целиком — особенно «Открытые вопросы» и «Критерии готовности»
3. Зафиксируй текущий статус

## Задачи нет в планах

Разовая мелкая правка — план не нужен. Заметное изменение поведения агента — создай план по `flow/meta/conventions.md` → «Планы улучшений flow», статус `proposed`, строка в таблице `README.md`.

```text
План для задачи:

Существующий план: [имя файла или «нет, нужно создать» или «разовая правка»]
Текущий статус: [proposed / approved / in_progress / done / нет]
Открытые вопросы плана: [короткий список]
```

**Остановка — только если создаётся новый план:** «Создаём план? 1 — ✅ да / 2 — ❌ это разовая правка».

# Шаг 3. Согласование открытых вопросов

Вопросы есть — задай их по одному за сообщение и жди ответов. Все разрешены — переведи план в `approved`, обнови `updated` и строку таблицы, сообщи одной строкой. Вопросов нет — переведи молча.

# Шаг 4. Реализация

Перед стартом — план в `in_progress`, `updated`, строка таблицы.

При изменениях:

- Не нарушай принципы из `flow/meta/overview.md`, включая правило безопасности удаления
- Соблюдай `flow/meta/conventions.md`
- Правка guard-хука или линтера — сначала тест-кейс в `flow/scripts/test_*.py`, потом правка
- Дополнительный контекст — расширяй минимально

# Шаг 5. Завершение

1. Сверь результат с критериями готовности плана
2. Правило плана стало стабильным — перенеси его в `flow/meta/conventions.md`
3. Изменилась карта файлов — обнови `flow/meta/structure.md`
4. Прогони `make flow-check` (полные `check-links`, `check-glossary`, `check-sizes`) и `make flow-test`. Ошибки чини, предупреждения — в отчёт
5. Правка инструкций — проверка симуляцией по `conventions.md` → «Проверка правок инструкций»
6. План в `done`, `updated`, строка таблицы

# Шаг 6. Финальный отчёт

1. Созданные файлы
2. Изменённые файлы
3. Изменения статусов планов
4. Затронуты ли файлы автозагрузки — отдельным блоком
5. Сообщение коммита одной строкой по [`flow/rules/naming-conventions.md`](../../../flow/rules/naming-conventions.md)
