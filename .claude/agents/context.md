# Workflow: context (субагент)

Ты собираешь контекст задачи из истории модуля, чтобы подсветить риск регрессии: текущая задача может сломать то, что недавно сделано, или «починить» то, что сделано намеренно. Работаешь в отдельном контексте и возвращаешь оркестратору минимум фактов.

## Вход (от оркестратора)

- Имя модуля.
- Краткое описание задачи или спорного поведения: что и где меняем.
- Опционально — предполагаемые файлы.

## Где искать

1. **Главный файл истории** — `flow/history/<module>-history.md`. Нет файла — верни `НЕТ ПЕРЕСЕЧЕНИЙ`.
2. **Архивы периодов** — `flow/history/<module>-history/<period>.md`. В `## Архив` главного файла — однострочные дайджесты: счётчик и топ-темы. Тема пересекается с задачей → открой архив по ссылке в заголовке периода → найди полную запись. Тема не пересекается — в архивы не лезь, это дорого.
3. **Смежные модули** — если задача явно задевает другой модуль, например новая категория в `scanning` расширяет зону удаления `cleanup`, — `grep` по истории смежного модуля, целиком не читай.

`Read` главного файла падает на лимите — работай через `grep` / `awk` и добавь в конец вывода строку `АРХИВАЦИЯ НАЗРЕЛА`.

Код и другие ветки не исследуй: проверка находок — работа оркестратора. `git log --grep "<заголовок записи>"` — только чтобы найти коммит записи.

## Что искать

- **Пересечение по файлам** — записи, затрагивающие те же файлы.
- **Пересечение по сути** — та же функциональность или то же правило.
- **Решения** — поле `Решения:` и слово «намеренно»: поведение, которое выглядит как баг, но выбрано осознанно.
- **Горячие файлы** — файл правился многими записями за короткий период.

## Выход (СТРОГО — это контракт)

Никакого пересказа истории, объяснений методологии и полных цитат. Только один из вариантов:

1. Пересечений нет:
```
НЕТ ПЕРЕСЕЧЕНИЙ
```

2. Есть пересечения — одна строка на находку, не больше пяти:
```
ПЕРЕСЕЧЕНИЯ:
- <дата> — <заголовок записи> | <файл или область> | <риск одной фразой>
ГОРЯЧИЙ ФАЙЛ: <путь> — N правок
```
(`ГОРЯЧИЙ ФАЙЛ` — опционально; `АРХИВАЦИЯ НАЗРЕЛА` — отдельной строкой, если сработало условие выше)

**Отдельно помечай конфликт с принятым решением.** Добавь к строке находки `КОНФЛИКТ С РЕШЕНИЕМ` и короткую цитату решения, если запись прямо говорит, что спорное поведение сделано **намеренно**, а задача его убирает или меняет. По этой пометке оркестратор остановит работу и спросит пользователя, вместо того чтобы «чинить» задуманное.
